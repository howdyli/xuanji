# 技能市场生态（社区发布/审核/安装）

## 背景与目标

代码库已具备完整的社区技能基础设施：`CommunityRegistry`（发布/安装/评价/收藏）、`community_skills` 表（含 `status: pending/approved/rejected/suspended`）、前端 `MarketplaceView` + `PublishSkillView`。

**核心缺口**：发布后技能停留在 `pending`，但没有任何 API/UI 能推进到 `approved`；市场列表只查 `status='approved'`，导致社区技能永远不可见。此外存在一个阻断安装的缺陷。

**本次目标**：补齐"发布 → 审核 → 上架 → 安装"闭环。

设计决策（已确认）：
- 审核权限：`users` 表增加 `is_admin` 布尔列，默认 `admin` 账户为管理员。
- 审核范围：仅首次发布需人工审核；版本/元数据更新沿用现有 `update_skill`（即时生效，不回退到 pending）。

## Phase 1: 数据层与权限

### 1.1 SQLite users 表增加 is_admin
文件：`xiaopaw/frontend/auth.py`
- `_init_db` 中对 `users` 表做幂等迁移：`ALTER TABLE users ADD COLUMN is_admin INTEGER NOT NULL DEFAULT 0`（用 try/except 或 PRAGMA table_info 检测，兼容已存在库）。
- `_init_default_admin`：创建默认 admin 时置 `is_admin=1`。
- `get_user` / `get_user_by_token` 返回值增加 `is_admin`（bool）。
- 新增方法：`is_admin(user_id) -> bool`、`set_admin(user_id, value)`（后者供运维/后续使用）。

### 1.2 community_skills 增加审计字段
文件：`schema.sql`（Postgres，幂等迁移）
```sql
ALTER TABLE community_skills ADD COLUMN IF NOT EXISTS reviewed_by  TEXT;
ALTER TABLE community_skills ADD COLUMN IF NOT EXISTS reviewed_at  TIMESTAMPTZ;
ALTER TABLE community_skills ADD COLUMN IF NOT EXISTS review_note  TEXT NOT NULL DEFAULT '';
```
`is_admin` 权威在 SQLite auth.db，不进 PG users 镜像。

## Phase 2: 后端审核 API 与安装修复

### 2.1 CommunityRegistry 审核方法
文件：`xiaopaw/skills_mgmt/community.py`
- `list_pending(page, page_size) -> {skills, total}`：查询 `status='pending'`，按 `created_at ASC`（先到先审）。
- `moderate_skill(name, action, reviewer, note='') -> dict`：`action in ('approve','reject')`，更新 `status='approved'|'rejected'`、`reviewed_by/reviewed_at=NOW()/review_note`，返回更新行；技能不存在抛 `CommunityError('not_found')`，非法 action 抛 `CommunityError('invalid_action')`。通过时 emit `CommunityEvent.SKILL_APPROVED`（若枚举无则复用现有事件/新增）。
- `set_featured(name, featured: bool) -> bool`：切换 `featured`（仅管理员用）。

### 2.2 修复本地发布技能无法安装（安装闭环关键）
文件：`xiaopaw/skills_mgmt/community.py` — `install_skill`
- 现状：`install_url = local://{dest}`，但 `MarketRegistry._default_fetch_archive` 拒绝非 http URL → 安装必失败。
- 修复：在 `install_skill` 下载分支前判断 `install_url.startswith('local://')`，直接从对应路径 `Path(...).read_bytes()` 读取归档（走 `asyncio.to_thread`），跳过 http fetcher；其余（http(s)）保持原逻辑。保留 `archive_hash` 校验。

### 2.3 审核 API 端点
文件：`xiaopaw/skills_mgmt/api.py`
- 新增 `_require_admin(request) -> dict | None`：先 `_get_current_user`，再 `request.app.get('user_auth').is_admin(user['id'])`；非管理员返回 None（handler 统一回 403）。
- 新增 handlers（前缀 `/api/frontend/market/community/admin`）：
  | 端点 | 方法 | 说明 |
  |------|------|------|
  | `/admin/pending` | GET | 待审核技能列表（分页） |
  | `/admin/skills/{name}/moderate` | POST | body `{action:'approve'|'reject', note?}` |
  | `/admin/skills/{name}/feature` | POST | body `{featured: bool}` |
- 在 `register_community_routes` 注册以上路由；admin 路径需在 `/{name}` 动态段之前注册以避免冲突（参照现有 `/publish` 注释）。
- `CommunityError` 映射：`not_found`→404，`invalid_action`→400。

## Phase 3: 前端

### 3.1 暴露 is_admin
- `frontend/src/types.ts`：`CurrentUser` 增加 `is_admin?: boolean`。
- `handle_auth_me` 已返回 `user` 全量字段，随 1.1 自动带出 `is_admin`，前端无需改后端。

### 3.2 管理员审核面板
文件：`frontend/src/components/market/AdminReviewView.tsx`（新建）
- 拉取 `GET /admin/pending`，卡片列表展示：名称、发布者、分类、版本、描述、SKILL.md 预览、截图。
- 每条提供「通过」「拒绝（可填原因）」按钮 → `POST /admin/skills/{name}/moderate`。
- 操作后刷新列表 + toast。

### 3.3 MarketplaceView 集成
文件：`frontend/src/components/MarketplaceView.tsx`
- `TopTab` 增加 `'review'`，仅当 `currentUser.is_admin` 时渲染「审核」Tab（带 pending 数量角标）。
- 选中时渲染 `AdminReviewView`。
- 组件需拿到当前用户：通过 props 传入或复用现有获取 `auth/me` 的方式（与 App.tsx 的 `currentUser` 对齐，优先 props 传入 `isAdmin`）。

### 3.4 我的发布状态可见
文件：`MarketplaceView` 的 my-skills 视图
- `list_my_skills` 已返回全状态；在「我的发布」列表为每条渲染状态徽章（待审核/已通过/已拒绝/已下架），拒绝项展示 `review_note`。

## Phase 4: 测试

文件：`tests/integration/test_skill_moderation.py`（新建）
- UserAuth：迁移后 `is_admin` 列存在；默认 admin `is_admin=True`；普通注册用户 `is_admin=False`；`set_admin` 生效。
- CommunityRegistry（需 PG，缺失时 `pytest.skip`）：发布→`list_pending` 含该技能→`moderate approve`→`list_skills` 可见→`moderate reject` 后不可见且 `review_note` 记录。
- 安装闭环：本地发布（`local://`）技能审核通过后 `install_skill` 成功解压。
- 权限：非管理员调用审核 API 返回 403。

## 风险与约束
1. is_admin 迁移需幂等，兼容已存在的 auth.db（检测列是否存在再 ALTER）。
2. 审核操作作用于 PG community_skills，管理员身份校验在 SQLite auth.db，两库通过 username/user_id 关联，无跨库事务需求。
3. 本地安装修复须防目录穿越：`local://` 路径限定在 `_storage_dir` 下再读取。
4. 向后兼容：未启用 PG 时社区功能整体降级（现状即如此），审核 API 返回 503。
5. 版本更新不触发重审属既定决策；如需"重大更新回退 pending"可后续迭代。
