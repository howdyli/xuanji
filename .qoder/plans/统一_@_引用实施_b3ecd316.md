# 统一 @ 引用（专家+技能）实施计划

## Summary
前端会话输入栏 `@` 弹出两栏浮层（专家/技能）：选专家保持现状（激活会话专家），选技能插入 `@技能名 ` token，发送时解析为 `skill_hints`（≤3）随消息提交；后端经 `InboundMessage.skill_hints` 在 runner 合成 agent 输入时前置显式指令行，强制点复用 SkillLoaderTool 的 `enabled_skills` 白名单。依据：`docs/superpowers/specs/2026-07-08-unified-mention-design.md`。

## 后端改动
- `xiaopaw/models.py`：`InboundMessage` 加 `skill_hints: list[str] = field(default_factory=list)`（放在 expert_name 之后）
- `xiaopaw/frontend/routes/session.py` `_prepare_message`：解析 `body.get("skill_hints")`，宽容校验——非 list 整体忽略；逐项要求 str、strip 后非空、≤64 字符；保序去重后截断至 3 个；结果传入 `InboundMessage`
- `xiaopaw/runner.py`（现 expert_prompt 合成处 L271 附近）：有 hints 时在用户内容前追加一行 `（用户为本条消息指定了优先使用技能：{", ".join(hints)}。请先通过 skill_loader 加载并使用它处理本条消息，除非明显不适用。）`；叠加顺序 expert_prompt → hint 行 → 用户内容；仅影响 agent 输入，不影响持久化 content

## 前端改动
- 新建 `frontend/src/components/MentionPicker.tsx`：两栏 Tab（专家/技能）浮层；专家栏复用 `ExpertPickerList`（含现 activeName 高亮）；技能栏数据源同 SessionSkillsPicker：`GET /skills` + `GET /sessions/{sid}/skills`（无绑定行 = 全部启用），仅列启用技能；`query` prop 同时过滤两栏；props：`{ open, anchorEl, sessionId, query, activeExpert, onSelectExpert, onSelectSkill, onClose }`；点击外部关闭
- `frontend/src/components/UnifiedInputBar.tsx`：
  - `!isHome` 时 @ 浮层由 `ExpertPickerPopover` 换为 `MentionPicker`；`isHome` 分支不动
  - `onSelectSkill(name)`：把正在输入的 @token（`MENTION_RE`）替换为 `@${name} `，关浮层、聚焦
  - 导出纯函数 `extractSkillHints(text: string, enabledSkills: string[]): string[]`：匹配 `@(\S+)` 且与启用技能名精确相等才计入，保序去重、最多 3 个
  - `handleSend`：调用 extractSkillHints，`onSend(trimmed, { skillHints })`（空数组时不传 opts）
  - `onSend` prop 类型改为 `(text: string, opts?: { skillHints?: string[] }) => void`
- `frontend/src/App.tsx` `handleSend`：接收并透传 opts，消息 API 请求体条件加 `skill_hints` 字段（含 stream 分支）

## Test Plan
- `tests/unit/test_frontend_routes.py`（或既有 _prepare_message 测试所在文件）：skill_hints 校验矩阵——合法两项、非 list（字符串/数字/None）、项非 str、空串项、>64 字符项、6 项截断为 3、重复去重；均不产生 4xx
- runner 注入单测：仅 hints、hints+expert_prompt 叠加顺序、无 hints 时内容原样（放入既有 runner 测试文件）
- 前端 `UnifiedInputBar.test.tsx` 补 extractSkillHints 用例（匹配/不在启用集/去重/上限）+ 新建 `MentionPicker.test.tsx` 渲染测试（两栏切换、过滤）
- 验证命令：`.venv/bin/python -m pytest tests/unit -x -q`、`cd frontend && npx vitest run && npm run build`
- E2E 手测（实现完成后询问用户是否执行）：重启后端 → kbe2e 会话中 `@某技能 <任务>` → 结构化日志确认 `before_tool_call: skill_loader` 加载指定技能

## Assumptions
- 技能名为 slug 形式（无空格），`@(\S+)` 可完整捕获
- 飞书通道不传 skill_hints，默认空列表零影响
- 完成后 commit（延续本会话已建立的提交习惯）
